# The exact dependency set the checked-in runs and reports were produced with.
#
# pyproject.toml carries ranges, because that is what the package supports. This file
# carries pins, because that is what it was actually run on. Ranges alone are not
# reproducible: pandas 2.1 and pandas 2.3 do not have to agree to the last decimal, and a
# report that quotes a t-statistic to two places should say which one it meant.
#
# It is a constraints file rather than a requirements file on purpose. Constraints only
# apply to packages pip is already installing, so the Windows-only and CPython-only lines
# below are ignored elsewhere instead of breaking the install.
#
#   pip install -c constraints.txt -e ".[dev]"
#
# Docker builds against it, and the pinned CI job installs with it so the file cannot rot
# unnoticed. The version matrix deliberately installs without it, because the point of
# that job is to prove the ranges in pyproject.toml still resolve.
#
# To regenerate after a deliberate upgrade, in a clean virtualenv:
#
#   python -m venv .fresh && .fresh/bin/pip install -e ".[dev]"
#   .fresh/bin/pip freeze --exclude-editable > constraints.txt
#
# then put this header back and re-run `make demo`, since the published numbers are tied
# to the code and the libraries together.
